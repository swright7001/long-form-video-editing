# First-use tool check and automatic setup

Run this procedure when the skill is invoked, before promising an edit. It is performed by Codex within the task; installing the skill alone cannot trigger an operating-system popup or a background installer. Show a concise status such as “Checking video tools; I’ll install missing dependencies needed for this edit.” Honor any user instruction to avoid installs, downloads or network access.

## Detect and plan

Detect the actual OS, CPU architecture, shell, available package manager, free disk space and the project's writable location. Check executable paths and run version/help commands rather than relying on file presence. Only inspect relevant tool locations; do not scan private folders or credentials.

Check FFmpeg and ffprobe for video processing. Check a supported Python runtime with pip/venv only if the chosen workflow needs Python. Check local transcription only if speech analysis or captions are needed and no usable transcript exists. Check yt-dlp only for a video-link request that requires a downloader. Do not install Node, Remotion, Manim, Docker, GPU drivers or an entire editor for an ordinary clip.

Reuse working tools. If a required component is missing, automatically resolve the latest stable release compatible with this OS, architecture and dependent tools, install it through the trusted route below, and continue. Do not ask a redundant setup question when the current user has authorized this workflow and the environment permits installation. This file cannot grant permissions on behalf of a new user or override their machine's approval policy. Handle a required approval through the normal tool interface; ask the user only when a password, administrator action, license acceptance, or unavailable permission actually blocks setup.

“Latest” means the newest compatible stable release available through the selected trusted distribution at setup time, not a hardcoded version or nightly build. Query current metadata before installing and record the exact selected and installed versions. Distribution packages may lag upstream; disclose that distinction. Never label an older distro build “latest upstream.” Do not upgrade working global tools merely because the skill was invoked. Resolve incompatibility with a project-local installation where practical.

## Trusted installation routes

- FFmpeg/ffprobe: start at https://ffmpeg.org/download.html for upstream releases and linked platform distributions. On macOS, prefer an existing Homebrew installation and its `ffmpeg` formula. On Windows, prefer an existing WinGet installation after verifying the exact FFmpeg package ID and publisher using `winget search` and `winget show`; do not guess package IDs. On Linux, use the existing distribution package manager and enabled trusted repositories. Query the package candidate first. If no suitable manager exists, use a compatible build linked by FFmpeg, verify its published checksum/signature when available, and install under a user-owned tool directory. Do not silently bootstrap a system-wide package manager or add unknown repositories.
- Python: use an existing compatible interpreter or resolve a stable supported version from https://www.python.org/downloads/ or the trusted OS package manager. Select compatibility with the transcription package rather than blindly installing the newest Python. Create a dedicated virtual environment in the footage project's tool directory, not the installed skill or system Python. Do not overwrite another environment.
- Local transcription: prefer an already working local engine. Otherwise consult https://github.com/openai/whisper and https://pypi.org/project/openai-whisper/ for current supported Python versions and the latest stable package. Use the exact package name `openai-whisper`, not `whisper`. Resolve the version, install that version in the dedicated virtual environment, and record resolved dependencies with `python -m pip freeze`. If compatible wheels/dependencies are unavailable, choose a documented compatible interpreter or report the issue instead of repeatedly compiling or changing global libraries.
- Model weights: software installation alone does not make transcription ready. Download a compatible official model into a user-owned cache when local transcription is required. Explain model name, approximate download size and CPU/GPU choice first. Choose a modest model suitable for the language and available resources; do not automatically download the largest model. Verify the upstream model checksum when supplied. Reuse cached weights. A model download does not authorize footage upload.
- Video-link downloads: consult https://github.com/yt-dlp/yt-dlp for the current stable release and runtime requirements. Install the official package in the isolated environment or use its official release distribution and verification information. Install extra runtimes only if the selected extractor needs them. Do not bypass source access restrictions or harvest browser cookies without applicable user authorization.

Use argument arrays and explicit paths for generated commands. Avoid remote shell pipelines, disabling security checks, unreviewed install scripts, or broad system updates. If an installer changes PATH, locate the executable in the current process or refresh the process environment; do not assume a new terminal has started. Prefer explicit tool paths over permanent shell configuration changes.

## Verify before claiming readiness

1. Run the installed FFmpeg and ffprobe version commands. Confirm required encoders/filters (for example H.264, AAC and the chosen caption method); missing libass need not block an alternative caption compositor.
2. Generate a tiny synthetic audio/video sample in a new project-local test directory, render it, probe it and decode it. Use no-overwrite behavior. If the edit needs burned-in captions, test the actual caption method with a sample cue and inspect a frame.
3. If transcription is needed, run the local engine's import/help check, confirm the selected model loads, then verify transcription on a short authorized local speech excerpt before processing the full recording. A help command alone is not a transcription test.
4. If a URL is supplied, verify downloader version and required runtimes; only retrieve the requested source. No network download test is needed for a local-only edit.
5. Save `toolchain.md` in the footage project's edit directory with OS/architecture, executable paths, installed versions, provider URLs, chosen model, completed checks and unresolved gaps. Never include secrets. Record setup status as ready only for capabilities actually verified.

On a failed installation, inspect the error and make at most one justified retry or documented compatible fallback. If blocked by permissions, unsupported hardware, disk space or network access, report the specific gap and continue independent work; do not loop indefinitely, silently use cloud processing or claim success. Later sessions recheck versions/capabilities cheaply and reuse the toolchain; rerun installation only when needed.
